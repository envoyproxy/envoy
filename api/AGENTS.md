# Guide for AI Agents: the xDS API (`api/`)

Instructions for AI agents changing the xDS API protos under `api/`. These protos are consumed by
many control planes and by xDS clients other than Envoy (e.g. gRPC), and the v3 API is never
broken, so mistakes here are permanent.

## Read first

Read these in full before changing any `.proto` file. They are the canonical API guidance; this
file deliberately does not repeat them.

- [API_VERSIONING.md](API_VERSIONING.md): what counts as a breaking change. CI does not check wire
  or JSON compatibility, so you must.
- [STYLE.md](STYLE.md): conventions, annotations, and how to document fields.
- [review_checklist.md](review_checklist.md): the questions API shepherds ask. Answer the relevant
  ones in the PR description.

## Workflow

1. Edit the `.proto` files. For a new extension, follow
   [Adding an extension configuration to the API](STYLE.md#adding-an-extension-configuration-to-the-api).
2. Commit, then run `./tools/proto_format/proto_format.sh fix` to regenerate `BUILD` files and
   formatting. The tool compares against the committed state, so commit before running it.
3. Build the docs (`./ci/do_ci.sh docs`) when comments change, since RST errors only show up there.

## Changing the API guidance

Pull requests that touch `api/` get a Copilot code review driven by
`.github/instructions/api-review.instructions.md`. Copilot may not reliably follow links, so that
file is generated by inlining API_VERSIONING.md, STYLE.md and review_checklist.md (minus procedural
sections listed in `tools/api/review_instructions/generate.py`) after the review-specific header in
`tools/api/review_instructions/header.md`. After editing any of them, run
`./tools/proto_format/proto_format.sh fix`; CI fails if the generated file is stale.

The header's `applyTo: "**"` is intentional. Path-specific instructions only apply to matching
files, so scoping it to `api/**` would let Copilot review the non-API files of a PR again, which is
what the "comment only on files under `api/`" rule prevents. The trade-off is that a Copilot review
requested by hand on a PR without API changes will have nothing to say.
