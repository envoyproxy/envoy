JWT handshake validation (proto)
================================


Configuration for verifying a bearer JWT during handshake authentication, shared by extensions
that authenticate a connection or request by validating a token.




.. _envoy_v3_api_msg_extensions.filters.common.jwks.v3.JwtHandshakeValidator:

extensions.filters.common.jwks.v3.JwtHandshakeValidator
-------------------------------------------------------


:repo:`[extensions.filters.common.jwks.v3.JwtHandshakeValidator proto] <api/envoy/extensions/filters/common/jwks/v3/jwt_handshake.proto#L34>`

Validation of a bearer JWT. A consuming extension verifies the token against the configured JWKS,
issuer, audiences, and time constraints. On success it publishes the verified claims as dynamic
metadata under ``claims_metadata_namespace``, so the consumer can bind a claimed identifier to a
verified claim via ``%DYNAMIC_METADATA(namespace:claim)%``. What a validation failure does, and
any per-field defaults, are defined by the consuming extension.

.. attention::
  Verifying the token proves only that the caller *holds* a valid token; it does **not** by itself
  prove the caller is the identity it claims. To authenticate the claimed identity, bind a verified
  claim from the consuming extension's own validation configuration. Without such a binding, a token
  minted for one identity can be presented for another. Tokens without an ``exp`` claim are
  rejected. All top-level claims are published as dynamic metadata (see
  ``claims_metadata_namespace``), so do not put secrets in the token.



.. code-block:: json
  :force:

  {
    "issuer": ...,
    "audiences": [],
    "local_jwks": {...},
    "remote_jwks": {...},
    "token_header": ...,
    "claims_metadata_namespace": ...,
    "allow_missing_or_failed": ...,
    "clock_skew_seconds": ...
  }

.. _envoy_v3_api_field_extensions.filters.common.jwks.v3.JwtHandshakeValidator.issuer:


issuer
  (`string <https://developers.google.com/protocol-buffers/docs/proto#scalar>`_, *REQUIRED*) Required. Expected token issuer. The JWT ``iss`` claim must equal this value.


.. _envoy_v3_api_field_extensions.filters.common.jwks.v3.JwtHandshakeValidator.audiences:


audiences
  (**repeated** `string <https://developers.google.com/protocol-buffers/docs/proto#scalar>`_) Allowed audiences. If non-empty, the JWT must carry at least one of these in its ``aud`` claim.
  If empty, the audience is not checked.


.. _envoy_v3_api_field_extensions.filters.common.jwks.v3.JwtHandshakeValidator.local_jwks:


local_jwks
  (:ref:`config.core.v3.DataSource <envoy_v3_api_msg_config.core.v3.DataSource>`) The JWKS provided inline as a data source (``inline_string``, ``inline_bytes``, or
  ``filename``). The keys are read once when the configuration is loaded.


  Source of the JSON Web Key Set (JWKS) used to verify the token signature. Exactly one source
  must be configured.


  Precisely one of :ref:`local_jwks <envoy_v3_api_field_extensions.filters.common.jwks.v3.JwtHandshakeValidator.local_jwks>`, :ref:`remote_jwks <envoy_v3_api_field_extensions.filters.common.jwks.v3.JwtHandshakeValidator.remote_jwks>` must be set.

remote_jwks

  Source of the JSON Web Key Set (JWKS) used to verify the token signature. Exactly one source

.. _envoy_v3_api_field_extensions.filters.common.jwks.v3.JwtHandshakeValidator.token_header:


token_header
  (`string <https://developers.google.com/protocol-buffers/docs/proto#scalar>`_) Name of the header carrying the token. When unset, the consuming extension applies its own
  default (commonly ``authorization``, with a leading ``Bearer`` prefix stripped).


.. _envoy_v3_api_field_extensions.filters.common.jwks.v3.JwtHandshakeValidator.claims_metadata_namespace:


claims_metadata_namespace
  (`string <https://developers.google.com/protocol-buffers/docs/proto#scalar>`_) Namespace under which verified claims are emitted as dynamic metadata. If unset, the consuming
  extension's default namespace is used. Each top-level JWT claim is written as a field in this
  namespace so it can be referenced via ``%DYNAMIC_METADATA(namespace:claim)%`` by the consuming
  extension's validation configuration.


.. _envoy_v3_api_field_extensions.filters.common.jwks.v3.JwtHandshakeValidator.allow_missing_or_failed:


allow_missing_or_failed
  (`bool <https://developers.google.com/protocol-buffers/docs/proto#scalar>`_) If ``true``, a missing or invalid token does **not** fail validation; the verified claims are
  simply not published. Useful for a staged rollout or audit mode. Defaults to ``false``. How a
  validation failure is handled is defined by the consuming extension.


.. _envoy_v3_api_field_extensions.filters.common.jwks.v3.JwtHandshakeValidator.clock_skew_seconds:


clock_skew_seconds
  (`uint32 <https://developers.google.com/protocol-buffers/docs/proto#scalar>`_) Clock skew, in seconds, allowed when checking the ``exp`` and ``nbf`` time constraints. When
  unset (``0``), the consuming extension applies its own default.
